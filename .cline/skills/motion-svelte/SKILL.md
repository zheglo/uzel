# Motion → Svelte 5 attachments

## Цель

Адаптировать ванильный JavaScript-код Motion под текущий
Svelte-проект, сохраняя визуальное поведение и используя
{@attach ...} для привязки к жизненному циклу DOM-элемента.

Не создавать универсальную библиотеку или дополнительную
архитектуру ради одного примера.

## Приоритет правил

Следуй AGENTS.md и текущей конфигурации проекта.

Этот skill не разрешает:
- самостоятельно менять файлы;
- запускать несогласованные команды;
- устанавливать зависимости;
- менять конфигурацию;
- выполнять несогласованный рефакторинг.

Если правило skill противоречит AGENTS.md,
сообщи об этом до реализации.

## Перед адаптацией

1. Прочитай исходный пример и целевой компонент.
2. Проверь установленную версию motion и существующие импорты.
3. Установи, что запускает анимацию:
   - появление элемента в DOM;
   - событие пользователя;
   - попадание в область видимости;
   - прокрутка;
   - изменение параметров.
4. Определи, какие ресурсы создаются:
   - анимации;
   - наблюдатели;
   - обработчики событий;
   - таймеры;
   - другие подписки.
5. Кратко предложи структуру адаптации и затрагиваемые файлы.
6. Получи согласие перед изменениями.

Если визуальное поведение или момент запуска непонятны,
спроси, а не придумывай.

## Документация

Для Svelte используй официальный Svelte MCP:
- list-sections;
- get-documentation;
- svelte-autofixer.

Проверь документацию {@attach ...}, а при необходимости —
тип Attachment и реактивность attachments.

Для Motion используй официальную документацию motion.dev
по конкретным функциям исходного примера.

Не подменяй ванильный API документацией React.
Не придумывай параметры и методы очистки.

Если необходимая документация недоступна,
сообщи об этом и укажи, что осталось непроверенным.

## Основной подход

- Используй ванильный JavaScript API пакета motion.
- Не добавляй Svelte-обёртки или motion-компоненты.
- Для DOM-интеграции предпочитай attachment,
  получающий конкретный элемент.
- Не используй onMount или use:action вместо attachment.
- Не добавляй отдельный $effect, если attachment уже
  решает задачу жизненного цикла.
- Не считай attachment универсальной заменой
  обычных обработчиков событий.

Оставляй код в компоненте, если он относится только к нему.
Выноси в отдельный .ts-файл при реальном повторном
использовании или заметном улучшении читаемости.

## DOM и область действия

- Основной элемент бери из аргумента attachment.
- Для вложенных элементов ограничивай поиск этим элементом.
- Не используй глобальный document.querySelectorAll
  для локальной анимации компонента.
- Не допускай, чтобы несколько экземпляров компонента
  управляли элементами друг друга.
- Если нужен внешний элемент, явно объясни способ
  его получения и согласуй решение.

Не обращайся к window или document на уровне модуля
ради инициализации анимации.
DOM-зависимую инициализацию выполняй внутри attachment.

## Реактивность

Учитывай, что attachment может запускаться повторно,
если меняются прочитанные им реактивные зависимости.

- Явно определи, какие параметры должны перезапускать
  анимацию, а какие — нет.
- Не читай лишнее реактивное состояние внутри attachment.
- Не создавай реактивные циклы.
- Не используй untrack автоматически:
  сначала объясни, почему зависимость нужно исключить.
- Не добавляй $state только ради хранения animation controls,
  если они не нужны для реактивного интерфейса.

## Сохранение поведения Motion

Сохраняй без необходимости не меняя:
- keyframes;
- duration, delay, easing;
- repeat и направление повторения;
- порядок и временные связи последовательностей;
- stagger;
- SVG-атрибуты и начальные состояния;
- условия запуска и остановки.

Не заменяй последовательность независимыми анимациями,
если это меняет синхронизацию.

Не переносись со старого API MotionOne на новый API
по памяти: проверь соответствие по документации.

Не добавляй ручной requestAnimationFrame,
если текущая задача уже решается API Motion.

## Очистка

Каждый attachment должен освобождать созданные им ресурсы,
если они требуют очистки.

Возвращай синхронную функцию очистки из attachment.

Для каждого ресурса отдельно проверь официальный
способ остановки или отписки.

Важно:
- stop и cancel не считать взаимозаменяемыми;
- не предполагать наличие cancel у любого объекта;
- не считать остановку анимации автоматическим
  восстановлением всех inline-стилей;
- не удалять весь атрибут style у элемента;
- при необходимости восстанавливать только те свойства,
  которыми управляла интеграция.

При повторном запуске attachment не должны накапливаться:
- активные анимации;
- обработчики;
- наблюдатели;
- таймеры.

Для async-логики:
- не делай сам attachment асинхронным;
- предусмотренную асинхронную работу запускай внутри;
- не допускай запуска новой анимации после cleanup;
- учитывай завершение или отмену предыдущей операции.

Не вводи дополнительную async-логику без необходимости.

## События

Если задача решается обычным onclick/onpointerenter
или другим обработчиком Svelte, не переноси её
в attachment искусственно.

Используй attachment для инициализации Motion,
привязки внешних подписок и управления их очисткой.

Избегай двух независимых владельцев одной анимации
или одного и того же обработчика события.

## Типизация

Используй простые типы.

При необходимости используй Attachment
из svelte/attachments.

Тип элемента должен соответствовать разметке:
HTMLElement, SVGElement или более конкретный тип.

Не применяй any и необоснованные приведения типов.
Не создавай сложные дженерики ради единичной анимации.

## Проверка

Перед передачей готового Svelte-кода пользователю
проверь его через svelte-autofixer.

Исправь относящиеся к задаче замечания и повтори проверку.
Если проблема не устранена, сообщи о ней явно.

Запусти pnpm check и pnpm lint только в согласованном
объёме и при наличии соответствующих скриптов.

Отдельно проверь или предложи проверить:
- совпадение поведения с исходным примером;
- повторное появление компонента;
- удаление компонента во время анимации;
- отсутствие влияния на другой экземпляр;
- перезапуск при изменении параметров, если он предусмотрен.

Не утверждай, что визуальная проверка выполнена,
если ты её не выполнял.
